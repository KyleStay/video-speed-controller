# StayFast 0.11.4

The production 0.11.3 settings handshake sends one request from the MAIN world
to the ISOLATED bridge. If the bridge starts later, the request is lost. After
two seconds MAIN aborts initialization and never attaches controls. A disposable
Chrome test reproduced this with the actual Web Store package by delaying only
the bridge bundle by 250 ms. Ordinary production startup and live YouTube also
passed; the affected user's exact site/browser conditions were not available.

The bridge now announces readiness after installing its listeners. A pending
settings request retries on that event and removes its temporary listeners when
settled. A persistent lifecycle listener recovers startup if readiness arrives
after the initial timeout. It preserves explicit teardown and coalesces pending
initialization. Disabled sites still require an allowed settings response.

Run `npm run test:e2e:startup` on macOS to verify the minified build with normal
startup, MAIN first, bridge first, and bridge arrival after the timeout. Each
case requires one controller and an actual keyboard-driven playback-rate change.
Unit tests cover retry cleanup and the initialized/pending/teardown guards.

The update also reconciles missed settings changes on visible-tab and persisted
history restoration, including enable/disable state and site rules. Recovery
rescans media and repairs removed indicators while preserving existing
controllers. Settings reads merge newer events per key, preserve removals, and
cannot replace a newer completed snapshot. Queued speed writes pause during
reconciliation: a changed or removed stored speed cancels the stale write, while
unchanged storage preserves the user's pending speed.

Run `npm run test:e2e:resume` for browser regressions that deliberately drop
storage notifications, hold a settings read, and remove controller UI while
mutation delivery is stopped. These controlled fixtures exercise the real built
worlds. The injected test hooks exist only in a disposable bundle copy and are
excluded from the upload ZIP. Standard local and live YouTube checks verify the
unmodified release build.

The focused upload candidate is in
`release/chrome-reliability-0.11.4/`. It is built from commit `93ba566` plus
the startup and restoration repairs, version bump, regression tests and documentation. The
separate Safari/UI work in the working checkout is excluded. `hotfix.patch`
records its source changes against that commit. `VALIDATION.md` records the
completed checks and package checksum. The public store still serves 0.11.3;
this candidate has not been uploaded or published. This ZIP supersedes the
earlier startup-only candidate in `release/chrome-startup-hotfix-0.11.4/`.

## Safari and iOS integration

The combined release also includes the native Safari containing app, adaptive
inline controls, explicit native fullscreen, custom playback with precision
scrubbing, scroll preservation, and optional local video-load diagnostics. Normal
play stays inline. See [Safari acceptance](../safari.md) and the
[TestFlight packet](../testflight.md) for release evidence and platform limits.
The focused Chrome ZIP described above is a historical independent candidate;
its validation does not cover this combined release.
