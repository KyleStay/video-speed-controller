# Chrome Web Store submission packet

Last verified against Google's official documentation: August 2, 2026.

This is the complete operator checklist for publishing the version currently set in `package.json`.
Do not upload the repository-root `dist.zip`; it contains a wrapping directory
and macOS metadata. Use the versioned ZIP in `release/` generated by
`npm run release:chrome`.

## 1. Before opening the dashboard

- Register a Chrome Web Store developer account, accept the agreement, and pay
  the one-time registration fee.
- Set the required publisher name to **StayTech**.
- Verify the developer contact email. Use an address that is monitored for
  policy, rejection, and takedown notices.
- Make <https://github.com/KyleStay/video-speed-controller> public, or publish
  equivalent product, support, and extension-specific privacy pages on
  `staytech.co` and update `manifest.json` plus the URLs below.
- Confirm these URLs are publicly reachable while signed out:
  - Homepage: <https://github.com/KyleStay/video-speed-controller>
  - Support: <https://github.com/KyleStay/video-speed-controller/issues>
  - Privacy: <https://github.com/KyleStay/video-speed-controller/blob/main/PRIVACY.md>
- Optional but worthwhile: verify ownership of `staytech.co` in Google Search
  Console so the store can show an official publisher URL.

The old `https://staytech.co/stayfast` URL returned HTTP 404 during this audit
and must not be used unless that page is published first.

## 2. Build the upload package

From the repository root:

```sh
npm ci
npm run release:chrome
```

Upload:

`release/stayfast-video-chrome-<version>.zip`

Calculate and record a fresh checksum for the exact file you upload; rebuilding
can change it.

Required package properties:

- `manifest.json` is at the ZIP root.
- Manifest version matches `package.json` and must be greater than every version previously
  uploaded for this item.
- Manifest V3 is used.
- The package contains no source maps, `.DS_Store`, `__MACOSX`, remote code,
  analytics, or backend client.
- The only named extension permission is `storage`. Site access is supplied by
  content-script match patterns because the product must control media on any
  page where the user uses it.

## 3. Add the item

1. Open the [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole/).
2. Choose **Add new item**.
3. Upload the versioned ZIP above.
4. If the dashboard reports a manifest or package error, fix the source,
   increment the version if a prior package with that version was accepted, run
   `npm run release:chrome` again, and upload the new artifact. Do not manually
   edit the generated ZIP.

## 5. Privacy practices tab

**Single purpose:**

> StayFast Video adds user-controlled speed, seeking, frame stepping, marker, and keyboard controls to HTML5 video and audio on webpages.

**Storage permission justification:**

> Storage is required to save the user's keyboard shortcuts, playback-speed preferences, controller appearance, enable/disable state, and per-site rules. These settings remain in Chrome extension storage and may be synchronized by Chrome when the user has browser sync enabled. StayTech does not receive them.

**Website/content-script access justification:**

> StayFast Video must run on webpages that may contain HTML5 video or audio so it can detect those media elements, display the user-requested controller, and perform playback commands. Processing is local to the page and browser. The extension does not collect or transmit page content, URLs, browsing history, or playback history. Access to file URLs remains off unless the user explicitly enables Chrome's “Allow access to file URLs” setting.

If the dashboard shows separate HTTP, HTTPS, or broad host-pattern fields, use
the same website-access justification for each.

**Remote code:** Select **No, I am not using remote code**.

**Data use:** Do not select any collected-data category. The extension does not
transmit data to StayTech or a third party. Its local access to website media
and locally stored preferences is described in the privacy policy and the
permission justifications above. If Google's form wording has changed to ask
about local processing or access rather than collection/transmission, disclose
**Website content** and **Web history/site access** as processed locally, and
state that neither is transmitted or retained as history.

Certify every applicable Limited Use statement: data is not sold, is not used
or transferred for unrelated purposes, is not used for creditworthiness or
lending, and is handled only to provide the disclosed media-control purpose.

**Privacy policy URL:**

<https://github.com/KyleStay/video-speed-controller/blob/main/PRIVACY.md>

Open that link in a signed-out/private browser window before submission. The
policy, dashboard answers, listing copy, and extension behavior must stay
consistent.

## 6. Test instructions tab

**Credentials required:** No

**Instructions for reviewer:**

> 1. Install the extension and open any page containing an HTML5 video or audio element. No account or test credentials are required.
> 2. Start playback. A small speed indicator appears over the media.
> 3. Press D to increase speed by 0.1×, S to decrease it, and R to reset to 1×.
> 4. Press Z or X to seek backward or forward. Pause a video and press comma or period to step one frame backward or forward.
> 5. Open the toolbar popup to choose a preset or custom speed.
> 6. Open Settings from the popup to edit shortcuts, preferences, appearance, and per-site rules.
> 7. The extension has no login, paid feature, analytics service, or external backend.

## 7. Distribution tab

- Visibility: **Public**. For a prelaunch policy review, **Private** or
  **Unlisted** is also possible, but Google applies the same review rules.
- Regions: **All regions**, unless StayTech has a legal or support reason to
  exclude a country.
- Pricing: **Free**.
- Trusted testers: optional; add Google Accounts at the publisher-account level
  if doing a private test first.

## 8. Final manual verification

The automated gate covers lint, the repeatable test suite, Chrome and Firefox
minified release builds/packages, and a local-fixture Chrome extension E2E
smoke test. Complete this final manual runtime pass before clicking Submit for
Review:

1. Extract the versioned ZIP to a temporary folder.
2. Open `chrome://extensions`, enable Developer mode, choose **Load unpacked**,
   and select the extracted folder.
3. Confirm there are no manifest or service-worker errors.
4. Exercise every step in the reviewer instructions on one ordinary HTML5 video
   and one audio page.
5. Check the toolbar popup, settings page, enable/disable cycle, keyboard
   shortcuts, per-site disable rule, and a page reload.
6. Compare the rendered popup/settings/controller to the uploaded screenshots.
7. Remove the unpacked test install when done.

## 9. Submit and launch

1. Review the Package, Store Listing, Privacy practices, Test instructions, and
   Distribution tabs for warnings.
2. Choose **Submit for Review**.
3. Use **deferred publishing** for the first release so approval does not launch
   before the final public URLs and support channel are ready. After approval,
   publish within Google's 30-day staged-submission window.
4. Monitor the verified developer email and respond to any reviewer request.
5. After publication, add the final Chrome Web Store URL to `README.md` and the
   StayTech product page, then announce only after a clean public install test.
